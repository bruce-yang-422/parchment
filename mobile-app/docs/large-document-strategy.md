# 大型文件讀取策略

## 目標

大型 TXT 不因誤開而造成卡頓或記憶體不足。來源永遠唯讀，閱讀中的記憶體用量不隨檔案大小線性增加。

## 開啟前預檢

Android 選檔結果、文件資訊與實際讀取均透過背景工作通道處理；由其他 App 使用「開啟方式」傳入文件時，啟動階段不先同步查詢文件提供者，避免慢速雲端或媒體提供者阻塞主執行緒。

選檔後先取得名稱、格式與 byte 長度，不讀取內容：

- `<= 2 MiB`：沿用完整載入，適合一般 Markdown／TXT。
- TXT `> 2 MiB`：進入分頁閱讀器，不建立完整 `String`。
- Markdown `2–8 MiB`：提示內容可能較慢，可選擇簡化純文字模式。
- Markdown `> 8 MiB`：預設只允許簡化純文字模式。
- `> 256 MiB`：拒絕在手機開啟，避免索引及儲存空間失控。

目前在分頁閱讀器完成前，程式先以 `2 MiB` 為直接載入硬上限，避免現有完整字串流程造成 OOM。

## TXT 分頁核心

- 來源抽象為可隨機讀取的 `DocumentByteSource`，Android SAF、iOS security-scoped URL 與一般檔案共用介面。
- 每塊讀取 `128 KiB`；切塊時修正 UTF-8 邊界，避免中文字被截斷。
- 畫面只保留目前區塊、前 1 塊及後 2 塊。
- LRU 最多保留 6 塊；淘汰時移除解碼字串與排版 Widget 參照。
- 使用 `ListView.builder` 建立可視段落，不建立涵蓋全文的單一 `Text`／`RichText`。
- 預讀只在捲動速度低時執行；快速滑動時停止預讀並優先載入目標位置。

穩定狀態的來源 byte cache 約 `768 KiB`，加上 UTF-16 字串、段落索引與 Flutter 排版快取，目標控制在 `8–16 MiB`，不隨小說總長度增長。

## 索引與跳轉

- 背景 isolate 以串流掃描換行，建立稀疏索引；每 256 行記錄一次 byte offset。
- 首屏先顯示，不等待全文索引完成。
- 進度以 byte offset 計算；儲存 `sourceId + byteOffset`，重新開啟後可直接回到附近區塊。
- 字數、行數與搜尋結果在掃描時漸進更新，不為顯示資訊而載入全文。
- 搜尋採串流掃描並分批回傳結果，結果數設上限，取消搜尋會立即停止 isolate。

## 釋放與取消

切換文件、App 進入記憶體壓力或離開閱讀頁時：

1. 增加 reader generation，使舊的非同步結果自動失效。
2. 取消預讀、搜尋與索引工作。
3. 關閉來源 handle／stream。
4. 清空 chunk LRU、段落 Widget key 與圖片快取參照。
5. dispose 捲動控制器；不保留完整文件內容於 controller 或最近開啟紀錄。

收到系統 memory pressure 時先清除離屏塊，只保留目前可視塊；仍不足時暫停預讀。

## Markdown 的限制

Markdown 的標題、註腳、參照、表格與跨段語法需要全文件狀態，不能直接以 TXT 分塊渲染。大型 Markdown 預設降級為安全純文字預覽；未來若要分段渲染，只能在完成區塊解析器與跨區塊狀態測試後啟用。

## 驗收標準

- 開啟 10 MiB、50 MiB、200 MiB TXT 時不建立等大的 Dart `String`。
- 首屏在中階手機 500 ms 內可讀；索引在背景進行且不阻塞滑動。
- 連續快速滑動不累積 chunk，LRU 上限始終有效。
- 反覆切換 20 份大型文件後，記憶體回到穩定基線附近。
- UTF-8 多位元字元跨 chunk、CRLF、超長單行及無效編碼都有測試。
